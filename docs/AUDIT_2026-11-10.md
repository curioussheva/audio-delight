## Jalur 1 — Initiation → Playback Control

### Peta alur (terverifikasi)

```
index.tsx: registerRootComponent(App) + require.context('./src/app') tanpa filter
  → MainApplication.kt: System.loadLibrary("pristine-audio")
  → src/app/index.tsx: has_onboarded? → /(drawer)/(tabs)/library : /onboarding
  → _layout.tsx performInitialization: POST_NOTIFICATIONS (33+) → requestAudioPermissions()
    → audioEngine.initialize() → initStore() → restore audio_mode_preference
  → Library library.tsx:537 → playerStore.playSong → dedupe + rotasi queue (workaround TrackQueue::setTracks
    yang selalu reset mCurrentIndex=0) → NativePlaybackService.setQueue → .play()
  → NativePlaybackService.kt → PlaybackNativeBridge → JNI nativePlay → PlaybackController::play()
    → engine start per-file rate (pickBestRate)
  → balik: 3 listener native + position watcher 500ms + syncFromNative
  → PlaybackService.kt (foreground, START_STICKY, PARTIAL_WAKE_LOCK) → MediaSessionManager.kt
    → notifikasi (callback sync balik ke JS, fix 2026-10-10)
```

### Temuan

**Major**
- **Audio focus TIDAK ADA sama sekali.** Grep `AudioFocus|requestAudioFocus|OnAudioFocusChangeListener|abandonAudioFocus` di `android/` + `src/` = nol. Telepon/notifikasi/YouTube → PristineAudio terus bunyi menumpuk.
- **Tidak ada `ACTION_AUDIO_BECOMING_NOISY`.** Headphone dicabut → audio lanjut keluar speaker. Hanya ada pembacaan status (`AudioDeviceInfo.kt:21`, `BluetoothA2dpStatus.kt`) — observasi, bukan handling.
- **Kontrol speed placebo.** Settings menampilkan stepper 0,5×–2,0× (`settings.tsx:947-997`), tapi `playerStore.setPlaybackSpeed` hanya set Zustand + AsyncStorage + warn `"belum didukung custom service"` (`playerStore.ts:827-833`); `engine.setPlaybackRate` stub (`engine.ts:289-290`).
- **Dua jalur play tidak setara.** Library pakai `playerStore.playSong` (dedupe, rotasi, persist). Search pakai `useAudioPlayer.loadSong` (`search.tsx:174`) — bypass store: queue native berisi 1 lagu → next/previous tidak jalan setelah play dari Search.
- **`AudioEngine` (`engine.ts`) sebagian besar MATI.** Hanya `initialize()`, `setProcessingMode()`, `toggleExclusiveMode()` punya caller. `play()`, `pause()`, `seekTo()`, `setQueue()`, `setEqBand()`, `applyDSP()`, `enableVisualizer()`, `destroy()` tanpa caller — jalur nyata adalah store → `NativePlaybackService` langsung. Perbaikan di `engine.play()` tidak berpengaruh ke playback nyata.
- **Gagal load native = crash tanpa pesan.** `TurboModuleRegistry.getEnforcing` throw sinkron saat import kalau modul hilang; `System.loadLibrary` crash (`UnsatisfiedLinkError`) kalau `.so` hilang. Belum pernah disimulasikan.
- **Race `setIsPlaying`** (belum terverifikasi live): `set({isPlaying})` setelah `await play()/pause()` (`playerStore.ts:696-770`) — tap cepat bisa berakhir stale.

**Minor**
- Position watcher 500ms tidak pernah `clearInterval` (`playerStore.ts:341`); polling ganda saat Search aktif.
- `initStore` restore queue pakai `db.execute` sinkron di JS thread (`playerStore.ts:208`) — potensi jank.
- `recoverUri` mengasumsikan MediaStore id == song id (`playerStore.ts:428`) — belum terverifikasi.
- `useAudioProgress` memalsukan `buffered = duration`. Sleep timer in-memory saja.
- File junk `src/app/_layout.tsx (2)` (305 baris): dead code tapi ikut ter-bundle (`require.context` tanpa filter); berisi `DUMMY_TEST_URI` (`/storage/emulated/0/Music/Enya_-_Dark_Sky_Island.flac`) + DUMMY AUTOPLAY 10 detik, dijaga `if (!__DEV__) return;` — risiko rendah, tapi path pribadi ikut terkirim di build.
- Cabang `needs_migration === "true"` kosong (`index.tsx:23-24`). Splash di-hide dari dua tempat.

**Yang terverifikasi baik**
- `initPlaybackModule()` **memang tanpa caller** (definisi `NativePlaybackModule.cpp:304`, deklarasi `.h:31`, nol pemanggil) — **tapi sudah moot**: native init jalan lewat lazy `getController()` (`:22-30`) + `getControllerAndStartEngine()` (`:38`); engine sengaja tidak di-start di `JNI_OnLoad` demi pemilihan laju per-file (`OnLoad.cpp:84-91`).
- Fix transisi 96kHz (dulu SIGSEGV) terverifikasi di kode: 3-lapis guard `swr_convert` (`FFmpegDecoder.cpp:212-283`), gain 0,89 sudah dihapus, seek/posisi sudah di domain laju yang benar.
- Background service + MediaSession lengkap dan benar; permission flow lengkap (`READ_MEDIA_AUDIO` per API level, `RECORD_AUDIO` sengaja tidak ada); onboarding fix 2026-10-09 terverifikasi (`setAudioMode` setelah `DSPPipeline.setProcessingMode`).
- Status exclusive sampai ke UI dengan jujur (`isExclusiveModeActive()` + `getActualSampleRate()`, `useBitPerfectStatus.ts` membedakan requested vs aktual).
- Asal bug "speed 2.00×" tidak ditemukan di kode — yang terbukti hanya kontrol speed yang tidak berfungsi.

## Jalur 2 — Tiga Mode Audio

### Peta rantai (terverifikasi)

```
playerStore.setAudioMode → engine.setProcessingMode → NativeDSPModule.setProcessingMode
  → JNI setNativeProcessingMode → EngineManager::setProcessingMode → AudioState (atomic)
  → AudioCallback::updateParameters (1x per buffer) → AudioPipeline::process() switch
```

| Mode | Pipeline | Pasca-pipeline |
|---|---|---|
| Bit-perfect | `processBitPerfect` = no-op sengaja (`AudioPipeline.cpp:108`) | sanitize saja (NaN/inf→0, \|x\|>2→0, denormal→0); tanpa limiter |
| DSP | `processDSP` → `applyDSPConfig` → `DSPChain::process` (HeadphoneCorrection → EQ 10-band → StereoWidener → Gain → Limiter) | limiter (identity < 0.98) + sanitize |
| Immersive | `processImmersive` → gain/balance constant-power → `ImmersiveStage::process` (Solfeggio → Harmonic → Spatial → Brainwave; tanpa DSPChain, tanpa EQ) | limiter + sanitize |

Nama JNI dan `external fun` Kotlin cocok persis. Jalur exclusive terpisah: `toggleExclusiveMode` → `reopenStreamPreservingPlayback()` → AAudio (exclusive) → OpenSLES fallback. USB DAC tersambung penuh (`audioOutput.ts` → `NativeDeviceModule` → `setDeviceId` di `AudioStreamController.cpp:260`; status jujur `[requested, actual, honored, pathLossy, rateHonored]`).

### Temuan

**Major**
- **M1 — Bit-perfect hilang diam-diam saat track berganti laju.** `PlaybackController::loadTrack()` hanya `setFileSampleRate(track.sampleRate)` (`:189`); `EngineManager::start()` hanya dipanggil dari JNI `startEngine` dan `reopenStreamPreservingPlayback()` (exclusive/device/dicabut). Auto-advance/next tidak me-reopen stream → track 96 kHz setelah 44,1 kHz tetap jalan di stream 44,1 kHz, decoder me-resample (`PlaybackController.cpp:579-613`). Ini langkah 3 `RATE_CHAIN_AUDIT.md` §5 yang masih BELUM.
- **M2 — Resampler produksi = interpolasi linear.** `StreamResampler.h:49` memakai `dsp::LinearResampler`; `AudioDecoder::applyResampling()` (`:225-260`) dipakai tiap chunk. Tanpa anti-aliasing: downsampling 96→48 kHz berpotensi aliasing. `SincResampler` tersedia + factory mendukung `SINC_FAST/MEDIUM/BEST`, tapi di-hardcode Linear.
  - **KOREKSI 2026-11-11 (audit decoder, `docs/AUDIT_NATIVE_CPP_DECODER_2026-11-11.md` D-M1):** klaim di atas tidak tepat. Resampler produksi `FFmpegDecoder` adalah **sinc libswresample** (`linear_interp=0`, `filter_size=128`, `cutoff=0.97`). Resampler linear ikut jalan di produksi sebagai resampler **kedua** untuk file non-48 kHz/non-stereo — di atas hasil sinc, dengan frame-count salah domain (`framesDecoded` domain input vs buffer domain output) → untuk 96 kHz: heap OOB read + SIGSEGV (terbukti harness ASAN); 44,1 kHz: tempo −8,8%; 96 kHz di stream 96 kHz: 2× cepat. Dan `SincResampler` bukan hanya tidak dipakai — `process()`-nya stub yang fallback ke linear, jadi harus ditulis ulang kalau mau dipakai, bukan "diaktifkan".
- **M3 — Badge bit-perfect UI tidak memeriksa laju.** `useBitPerfectStatus.ts:73-95`: `isBitPerfect = requested && exclusive` — tanpa membandingkan laju stream vs file. `rateHonored` sudah tersedia dan ditampilkan sebagai peringatan terpisah (`settings.tsx:586`, `analyzer.tsx:432`), tapi badge di `player/index.tsx:148` dan `settings.tsx:766` hanya memakai `exclusiveFailed`. Kombinasi M1+M3: UI bisa menampilkan bit-perfect sementara sampel sedang diresample.
- **M4 — Parameter immersive tidak bisa diubah user; brainwave tidak pernah jalan.** Nol pemanggil TS untuk `setSolfeggioFreq` / `setBrainwaveFreq` / `setResonanceIntensity` / `setImmersiveEnabled` (hanya deklarasi di spec + `nativeInterface.ts`).
